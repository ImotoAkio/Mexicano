Falhas — Dashboard.tsx

Weather API mostra dados fabricados sem aviso

Bug Dashboard.tsx:292-293
›

Quando a API de clima falha, o código silenciosamente define setWeather({ temp: 24, desc: 'Ensolarado' }). O usuário vê dados meteorológicos fabricados sem nenhuma indicação de que são fallback. Em uma plataforma náutica, isso pode afetar decisões operacionais.

Falhas — WhatsAppPage.tsx

Botão "Cancelar envio" não funciona — useState ao invés de useRef

Crítico WhatsAppPage.tsx:258, 475-485, 541-544
›

cancelSendingRef é declarado como useState<boolean>, não useRef. O loop async captura o valor inicial (false) do closure. Quando setCancelSendingRef(true) é chamado, o loop já em execução nunca vê o novo valor e as mensagens continuam sendo enviadas para todos os destinatários.

// Problema:
const [cancelSendingRef, setCancelSendingRef] = useState<boolean>(false);
// Deveria ser:
const cancelSendingRef = useRef<boolean>(false);

Sem mecanismo de cancelamento para confirmações e bloqueio

Crítico WhatsAppPage.tsx:621-678, 833-913
›

Ambas funções são loops async com delays de 4-5s entre envios. Não existe botão stop, abort, ou qualquer forma do usuário interromper o processo. Envio acidental de mensagens de bloqueio para dezenas de clientes não pode ser parado.

Problemas Transversais

Lógica boatCode duplicada em 4+ locais — O padrão boat.numero ? `M${boat.numero}` : boat.nome.split(' ')[0] aparece em SchedulesPage, ScheduleCard, StatusModal e BulkWhatsAppModal. Já existe getBoatCode() como utilitário mas não é usado consistentemente.
Acesso direto ao DB durante render — Múltiplos componentes chamam clientDB.getById(), boatDB.getById() e getAll() diretamente durante renderização, bypassando o state management do React. Atualizações via socket não causam re-render nesses valores.
Inconsistência de timezone entre componentes — Existem pelo menos 3 implementações diferentes de "data local": toISOString().split('T')[0] (UTC), getLocalDateStr() manual, e new Date(date + 'T12:00:00'). Cada uma falha em cenários diferentes próximos à meia-noite.
Gerenciamento de conexão WhatsApp duplicado — WhatsAppPage e FinanceWhatsAppPage implementam independently a conexão, auth headers, save/load de templates, loops de envio com delay e error handling. Uma camada compartilhada (hooks/serviço) reduziria duplicação significativamente.
Nenhum envio de mensagem usa queue server-side — Todos os loops rodam no browser. Fechar a aba perde o progresso sem registro. Múltiplos admins enviando simultaneamente podem exceder o rate limiter (300 req/60s) sem feedback.
